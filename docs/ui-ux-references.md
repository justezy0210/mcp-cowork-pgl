# 연구실 웹 플랫폼 UI·UX 참고 조사

조사일: 2026-09-26

추천 방향은 **Linear의 목록·탐색 구조 + Benchling의 보관 위치 관리 + Seqera의 작업 상세 구조**다.
샘플 관계는 LabKey, 데이터 변경 이력은 Nextcloud, 간단한 재고 등록은 eLabFTW를 보조 참고한다.
아래 ‘공식 문서의 패턴’은 공개 문서에서 확인한 내용이고, ‘우리 플랫폼 적용안’은 이를 바탕으로 한 제안이다.
각 제품의 로그인 후 실제 사용성이나 연구실 구성원의 선호를 검증한 결과는 아니다.

## 조사 기준

기존 요구사항은 서버 예약 현황·작업 조회, SSH 환경 등록, 사용자별 서버 권한, 개인 토큰과
Discord 설정, 종자·샘플·시약·소모품 재고, raw 데이터의 위치·변경 이력이다.
현재 웹 구현은 개인 토큰 화면이며 나머지는 확장 대상이다.
웹의 계산 영역은 조회·설정 관리 중심이고, 작업 명령 실행·취소는 MCP와 CLI에서 수행한다.

참고 대상은 실무 목록 검색, 개별 항목 상세 확인, 물리적 위치 표현, 상태·이력의 명확성,
초기 사용자의 설정 흐름을 기준으로 선정했다.

## 우선 참고할 여섯 제품

| 참고 대상 | 공식 문서의 패턴 | 우리 플랫폼 적용안 | 적용 범위와 주의점 |
| --- | --- | --- | --- |
| [Linear — Custom Views](https://linear.app/docs/custom-views) | 필터를 저장한 뷰, 즐겨찾기, 사이드바와 속성별 필터 | `내 작업`, `대기 중`, `내 샘플`, `확인 필요` 등 자주 쓰는 목록에 바로 접근 | 첫 버전은 정해진 필터부터 제공하고 사용자 정의 뷰 편집기는 후속 검토 |
| [Benchling — Inventory](https://help.benchling.com/hc/en-us/articles/39943809066637-Create-and-track-samples-with-the-Inventory) | 위치·용기·샘플의 계층, 박스 위치 선택, 수량·단위와 이동 관리 | `보관실 → 냉장고/보관장 → 선반 → 박스 → 위치`와 품목별 수량 표시 | 실제 보관 구조에 맞추며 모든 종자·소모품에 냉동고나 well 격자를 강제하지 않음 |

| [LabKey — Manage Samples](https://www.labkey.org/limshelp/wiki-page.view?name=viewSampleSets) | 샘플 상세의 보관 정보, Lineage·Aliquots·Timeline 등 탭 | 종자·샘플의 기본 정보, 보관 위치, 관련 데이터, 변경 이력을 묶은 상세 페이지 | 부모·파생 샘플 관계는 기록 모델이 정해진 뒤 적용. 식물 계통·세대는 별도 도메인 필드 |
| [Nextcloud — Activity](https://docs.nextcloud.com/server/latest/user_manual/en/activity.html) | 날짜별 활동 목록, 파일별 활동 사이드바, 변경 유형 필터 | 데이터의 기록된 위치와 이동·이름 변경 이력을 함께 확인 | 우리 시스템은 전용 CLI·에이전트가 기록한 변경부터 보여 주며, 웹 파일 이동 기능을 추가하는 의미는 아님 |
| [eLabFTW — Inventory](https://doc.elabftw.net/docs/usage/inventory/) | 위치 계층을 만든 뒤 용기의 수량·단위를 입력하고 위치 선택 | 시약·소모품과 다양한 용기의 간단한 등록 흐름 검토 | 실험노트 전체 기능은 현재 범위가 아님. [공식 사이트의 데모](https://www.elabftw.net/#try)에서 추가 비교 가능 |

위 링크에는 기능 설명과 화면 예시가 있다. Seqera는 `Tasks`와 `Task details`, Benchling은
`Create containers`와 `Fill boxes and plates`, LabKey는 `View Individual Sample Details`,
Nextcloud는 `Activity in the Files sidebar`를 먼저 보면 된다.

실제 목록 컴포넌트의 동작 기준은 [IBM Carbon Data table](https://carbondesignsystem.com/components/data-table/usage/)을
함께 참고한다. 검색·정렬·페이지 이동·선택 행의 일괄 작업을 일관되게 구성하는 데 유용하다.
이는 Carbon 라이브러리 도입을 확정한 것이 아니라 상호작용 규칙을 참고하는 제안이다.

## 권장 화면 구성

왼쪽에는 기능 메뉴, 중앙에는 검색·필터·목록, 오른쪽에는 선택 항목의 간단한 상세 정보를 둔다.
상세 정보가 길거나 관계·이력을 함께 볼 때는 별도 상세 페이지로 이동한다.
목록으로 돌아오면 필터와 스크롤 위치를 유지하는 것을 목표로 한다.

| 메뉴 | 처음 보여 줄 내용 | 주요 탐색 흐름 |
| --- | --- | --- |
| 홈 | 내 실행·대기 작업, 확인이 필요한 항목, 최근 변경 | 요약을 누르면 같은 조건의 목록으로 이동 |
| 서버·작업 | 허용 서버의 예약 예산·예약량·예약 가능량, 내 작업 목록 | 서버/상태 필터 → 작업 요약 → 상세 |
| 종자·샘플 | 이름·ID·유형·보관 위치·기록된 수량·담당자 | 검색 → 항목 상세 → 관련 데이터·이력 |
| 시약·소모품 | 품목·로트·수량/단위·보관 위치, 해당하면 유효기간 | 품목 검색 → 위치·수량 확인 |
| 데이터 | 데이터 ID·이름·기록된 위치·마지막 확인 시각 | 검색 → 상세 → 이전/이후 경로와 변경 이력 |
| 내 설정 | 개인 토큰, SSH 환경, 연결 프로그램 상태, Discord 상태 | 준비되지 않은 단계에 맞는 안내 |
| 관리 | 사용자 승인, 서버 이용 권한, 환경 등록 요청 | 승인 대기 목록 → 요청 내용 확인 → 반영 상태 |

홈의 재고 부족·유효기간 알림은 해당 필드와 기준이 정해진 경우에만 포함한다.
현재 존재하지 않는 데이터에 임의의 숫자나 그래프를 넣지 않는다.

## 우리 환경에서 중요한 UX

1. **예약량과 실제 사용량을 구분한다.** 서버 화면의 기본 표기는 `예약 CPU 24 / 64`처럼 한다.
   CPU 사용률 그래프로 바꾸지 않는다. GPU는 장치별 예약 여부를 보여 준다.
2. **대기 이유를 문장으로 표시한다.** `GPU 1장 대기`, `신청 메모리보다 예약 가능량 부족`처럼
   설명한다. 작업 종료 시간을 모르면 예상 시작 시각이나 정확한 대기 순번을 약속하지 않는다.
   현재 정책은 접수 순서 중 실행 가능한 작업부터 배정한다.
3. **물리적 위치와 파일 경로를 서로 다른 형태로 표시한다.** 샘플은 위치 계층,
   데이터는 저장소·경로·확인 시각을 사용한다. 둘을 연결하더라도 하나의 ‘폴더’로 취급하지 않는다.
4. **데이터 위치의 신선도를 보여 준다.** `마지막 확인`, `기록 전송 대기`, `확인 필요`를 구분한다.
   전용 도구 밖의 이동까지 자동으로 알고 있는 것처럼 표시하지 않는다.
5. **내 작업과 공유 현황을 구분한다.** 공유 목록은 필요한 예약 요약을 보여 주고,
   타인의 명령·로그·개인 경로는 일반 사용자에게 노출하지 않는다.
6. **승인과 연결 상태를 분리한다.** Google 로그인 완료, 관리자 계정 승인, SSH 환경 검증,
   연결 프로그램 접속은 별개 상태로 표시한다. 어떤 단계가 남았는지 안내한다.
7. **빈 목록과 연결 실패를 구분한다.** 응답이 없으면 ‘0건’ 대신 마지막 조회 시각과 갱신 실패를 보여 준다.
   Firebase 중계 방식을 선택한다면 요청 접수와 허브 반영 완료도 별도로 표시해야 한다.

## 시각적 방향 제안

- 밝은 중립 배경과 얇은 구분선을 기본으로 하고, 강조색은 하나로 제한한다.
- 상태는 색과 `대기`, `실행 중`, `실패` 같은 문구를 함께 사용한다.
- 이름·ID·수량·단위·위치가 쉽게 읽히도록 목록 너비를 확보한다. 긴 경로는 복사와 전체 보기 기능을 둔다.
- 데스크톱은 표 중심으로 구성한다. 모바일은 핵심 열과 상세 화면을 우선하고,
  키보드 포커스와 터치로도 주요 동작에 접근할 수 있도록 설계한다.
- 대시보드는 내 작업과 확인할 항목을 우선 배치하고, 전체 합계는 보조 정보로 둔다.

## 다음 디자인 작업의 범위

아래 세 화면의 첫 시안을 작성했다. 검색·필터·상세 이동이 가능한 예시 데이터 화면이며,
실제 데이터 연결과 배포는 아직 하지 않았다. [시안 열기와 검토 흐름](ui-preview.md)을 따른다.

1. **서버·작업:** 예약 현황, 상태 필터, 대기 이유와 작업 상세.
2. **종자·샘플:** 검색 가능한 목록, 위치 계층, 한 항목의 상세 정보.
3. **데이터 상세:** 기록된 위치, 마지막 확인 시각, 이름·위치 변경 이력.

종자·샘플과 재고의 필수 필드, 편집 권한, 초기 웹에서 허용할 변경 작업은 이 시안을 확인하며
정할 수 있다. 이번 조사로 새로운 기능이나 데이터 스키마를 확정하지 않는다.
