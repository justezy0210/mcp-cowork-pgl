# 현재 컨테이너에서 허브의 허가를 받아 실행하기

사용자 측 실행 스크립트가 허브에 자원을 신청하고, 해당 작업의 예약 허가를 받으면 현재
컨테이너에서 명령을 실행한다. 허브는 Docker나 SSH로 프로세스를 직접 실행·중지하지 않는다.
앞서 안내한 물리 호스트의 `docker inspect`, Docker 소켓 연결, 호스트 Worker 설치는 필요 없다.

## 현재 확인 상태

- 사용자 지정 물리 서버: `226`, 현재 컨테이너 이름: `b7c7d9a918a5`.
- 실행 사용자: `ezy`, UID `1101`, 기본 GID `1100`. GPU 없음.
- 작업 경로: `/10Gdata/ezy/01_Programs/cowork-mcp`.
- 허브: `http://192.168.10.41:8080`. 개인 토큰을 사용하는 MCP 조회는 확인했다.
- 운영 허브 배포·환경 승인을 완료하고 실제 작업 두 건과 Discord 알림 4건을 검증했다.

## 실행 흐름

1. 스크립트가 본인 계정과 등록 환경으로 CPU·메모리·GPU를 신청한다.
2. 허브가 권한과 예약 원장을 확인해 대기 또는 해당 작업의 실행 허가를 반환한다.
3. 스크립트가 허가를 기다린다. 가용량 조회 결과만으로 실행하지 않는다.
4. 허가를 받으면 현재 사용자의 권한으로 명령을 실행하고 실제 시작을 보고한다.
5. 명령과 필요한 하위 작업이 끝나면 종료코드를 즉시 보고한다.
6. 허브가 예약을 반환하고 다음 작업을 허가한다. Discord 알림은 별도로 처리한다.

현재 컨테이너에서 실행할 때 SSH는 필요 없다. 다른 컨테이너는 사용자 측 SSH로 접속해
그곳의 실행 스크립트를 사용한다. `ssh-copy-id` 등으로 인증이 준비되고, 실제 접속과 필요한
프로그램·입력 접근이 가능해야 한다. 허브에 SSH 개인 키를 제공하지 않는다.
SSH 접속 가능 여부와 허브의 허용 서버 정책은 함께 적용한다.

에이전트나 SSH가 종료되어도 계속 대기·실행하려면 실행 스크립트의 수명을 해당 세션과 분리한다.
이 역시 컨테이너 안에서 처리하며, 호스트 Docker 관리 권한은 필요 없다.

## 현재 사용

설정은 `.local/runner-226.json`이며 허브 업데이트·환경 승인·기존 Discord 채널 연결을 완료했다.
[로컬 실행 안내](local-runner.md)의 명령으로 제출할 수 있다. 시험 결과는
[운영 검증 기록](verification-226.md)에 정리했다. 작업 제출·취소 MCP 도구도 같은 로컬 실행기에 연결했다.
[MCP 안내](mcp-setup.md)의 선택지·제출·재시도 규칙을 따른다.
