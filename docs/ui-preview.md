# 연구실 플랫폼 UI 시안

2026-09-26: [UI·UX 조사](ui-ux-references.md)를 바탕으로 연구실 플랫폼의 동작 가능한 시안을 작성했다.
밝은 중립 배경과 초록 강조색, 공통 왼쪽 메뉴, 목록에서 상세로 이동하는 구조를 사용한다.

## 열기

저장소의 `src/cowork_hub/web/preview/index.html`을 브라우저에서 열면 된다.
같은 폴더의 `preview.css`와 `preview.js`가 필요하다. 로그인이나 서버 실행은 필요 없다.
이번 검토용 단일 HTML은 `.local/verification/ui-preview/cowork-preview.html`에 별도로 준비했다.
원격 서버의 파일을 PC 브라우저에서 보려면 이 단일 HTML을 PC로 저장한 뒤 연다.

허브의 정적 파일에 이 변경을 적용하면 `/web/preview/`에서도 열 수 있다.
이번 작업에서는 운영 허브를 업데이트하거나 Firebase에 배포하지 않았다.
기존 `scripts/build_web.py`는 개인 토큰 화면을 배포하는 도구이며 이 시안은 포함하지 않는다.

## 확인할 흐름

| 화면 | 구현한 상호작용 |
| --- | --- |
| 서버·작업 | 상태·서버·검색어의 조합 필터, 빈 결과 안내, 작업 상세, 대기 이유·신청 자원 확인 |
| 종자·샘플 | 종·유형·검색어(종·조직·부위 포함)의 조합 필터, 샘플 상세, 박스 내 위치 표시, 관련 데이터로 이동 |
| 데이터 | 데이터셋 검색·선택, 기록된 경로 복사, 연결된 샘플 조회, 변경 전후 경로와 시간별 이력 |
| 서버 사용 신청 | 서버 ID·UID·GID·컨테이너 SSH 포트 입력, 이미 허용된 서버 제외 안내, 신청서 미리보기·복사 |
| 개인 토큰 | Google 로그인→발급→user.token 다운로드 안내, 허브에서 열면 기존 토큰 발급 화면으로 이동, 파일 보관·교체 안내 |
| MCP 설치·사용 | 설치·사용법·문제 해결 전환, Codex/Claude Code 연결 명령 선택, 단계별 안내 펼치기, 명령 복사 |

서버 사용 신청은 서버 ID·UID·GID·컨테이너 SSH 포트 네 항목만 입력한다. 사용 이유는 받지 않고 신청자는 현재 사용자 정보에서 정한다.
서버마다 접속 포트가 다를 수 있으므로 한 건에 서버 한 대를 신청한다. UID/GID는 0~4294967295, 포트는 1~65535 범위의 정수만 받는다.
신청서는 현재 브라우저 메모리에서만 작성한다. 관리자에게 전송하거나 DB에 저장하지 않으며,
완료 화면에도 ‘미전송’을 표시한다. 서버 ID는 관리자가 안내한 값을 입력하고, 허용되지 않은 서버의
예약 현황을 신청 페이지에서 보여주지는 않는다. 실제 접수·관리자 승인 화면과 API 연결은 후속 구현이다.
요청자 신원은 운영 연동 시 인증 결과에서 결정해야 하며 폼의 입력값을 신뢰해서는 안 된다.

개인 토큰은 왼쪽 메뉴와 설치 안내에서 접근한다. 실제 발급·다운로드·폐기는 기존 `/web/` 화면과
인증된 `/v1/web/tokens` API를 사용한다. 시안을 HTTPS의 `/web/preview/`에서 열면 같은 허브의
발급 화면 링크가 활성화된다(로컬 개발용 HTTP 루프백도 허용). 단일 HTML이나 다른 정적 경로에서는
운영 주소를 추측하지 않고 안내만 표시한다. 시안의 예시 사용자 정보는 실제 인증에 사용하지 않는다.
새 서버 승인 시 기존 사용자 토큰을 계속 사용하며 서버 신청서 작성만으로 토큰을 발급하지 않는다.
운영에서 실제 파일을 받으려면 Firebase 로그인·허브 계정 연결·HTTPS 구성이 완료되어 있어야 한다.

MCP 안내는 [신규 사용자 매뉴얼](first-user-guide.md)과 실제 설치 스크립트를 바탕으로 한다.
메인 컨테이너의 경로·토큰 준비, 클라이언트 설치, 환경 등록·승인, MCP·스킬 연결, 첫 작업과 SSH 사용을 다룬다.
명령은 예시 경로를 본인 값으로 바꾼 뒤 사용하며 페이지에서 실행되지는 않는다.
연결 명령은 [Codex 공식 MCP 문서](https://developers.openai.com/codex/mcp/)와
[Claude Code 공식 MCP 문서](https://code.claude.com/docs/en/mcp)에 대조했다.
설치·배포 스크립트가 새 웹 하위 폴더를 파일로 읽지 않도록 웹 파일 수집을 재귀 탐색으로 수정했다.

서버 예약 현황·서버 수·서버 필터 선택지는 현재 사용자의 `allowed_nodes`에 포함된 서버로 제한한다.
허용 서버가 없으면 관리자에게 권한을 요청하는 안내를 표시한다.
시안의 ezy는 예시 서버 224·226·228·229를 모두 허용받은 것으로 설정되어 있다.
이 값은 화면 검토용이며 실제 권한을 변경하지 않는다. 운영 연동 시에는 인증된 `/v1/cluster` 응답을 사용해야 한다.
해당 API는 토큰의 사용자 ID와 DB의 grants를 기준으로 허용 서버만 반환한다.
내 작업 이력은 기존의 소유자 기준 조회 정책을 유지한다.

왼쪽 카테고리는 샘플의 `species` 필드에서 종별 목록과 건수를 만든다.
현재 예시 8건은 모두 벼이므로 ‘전체 종 / 벼’가 표시된다. 다른 종의 기록이 추가되면 카테고리도 생긴다.
종을 선택하면 보관 위치에 관계없이 같은 종의 시료를 조회한다. 박스 위치 열과 상세의 보관 경로는 유지한다.

샘플의 `유형`(종자·조직·DNA)과 `조직·부위`(종자·잎·뿌리)는 별도 필드다.
DNA의 조직·부위는 추출한 유래 조직을 뜻한다. 값이 없으면 ‘미기록’으로 표시하며 이름에서 추정하지 않는다.
목록·상세·모바일에 표시하고 기존 검색에서도 찾을 수 있다.

작업·샘플·데이터셋 목록은 기본 5개씩 표시하며 페이지당 5·10·25개를 선택할 수 있다.
하단에 표시 범위·검색 결과 수, 현재 페이지와 이전·다음 버튼을 표시한다.
검색·필터·페이지당 개수를 변경하면 첫 페이지로 돌아간다. 화면 이동 시 각 목록의 페이지는 유지한다.
검색 결과가 없거나 첫·마지막 페이지이면 이동할 수 없는 버튼을 비활성화한다.
샘플에서 관련 데이터를 열면 해당 데이터가 있는 페이지로 이동하고 상세를 표시한다.
현재는 예시 배열을 브라우저에서 나누며, 실제 DB·API 페이지 조회는 포함하지 않는다.

데이터 화면의 `Nipponbare · RNA-seq`는 현재 위치를 확정할 수 없는 경우의 예시다.
마지막 확인 위치와 ‘확인 필요’를 표시한다. 샘플 `SEED-0244`는 실물 수량 재확인이 필요한 예시다.
숫자·명령·샘플·파일 경로·이력은 모두 화면 검토용이며 실제 연구 기록이 아니다.
서버 이름도 레이아웃 검토를 위한 예시로 사용하며 표시 자원량은 실제 서버 명세가 아니다.

## 동작 범위

시안은 정적 파일만 읽고 Firebase·허브 API에 요청하지 않는다.
작업 실행·취소, 재고 수정, 실제 파일 이동, 알림 전송, 신청서 전송·승인이나 토큰 발급은 수행하지 않는다.
기존 개인 토큰 페이지와 로그인 코드는 변경하지 않았다.

모바일에서는 작업의 서버·신청 자원·대기 이유와 샘플의 유형·조직·부위·수량·위치를 이름 아래에 표시한다.
화면을 오가도 목록 필터를 유지한다. 상세 패널은 닫기 버튼이나 Escape로 닫는다.
클립보드 접근이 허용되지 않으면 경로를 선택하고 직접 복사하도록 안내한다.

## 검증

임시 Chromium에서 화면 이동, 필터 조합, 빈 결과, 상세 열기·Escape 닫기, 샘플→데이터 연결,
확인 필요 상태, 경로 복사 안내, 검색 입력 처리, 필터 유지, 모바일 배치와 단일 HTML을 검증했다.
조직·부위 열, 유래 조직으로 DNA 검색, 상세·모바일 표시도 확인했다.
페이지 경계·개수 선택·필터 초기화·다른 페이지의 관련 데이터 연결도 확인했다.
검증 전용 파일에 다른 종을 추가해 카테고리·건수 자동 생성과 종·유형·검색 조합도 확인했다.
허용 서버 2대·0대와 더 이상 허용되지 않는 서버 필터 초기화도 확인했다.
신청서 필수값·단일 서버 ID·UID/GID·SSH 포트·이미 허용된 서버 검사, 미전송 미리보기·복사,
설치 안내의 클라이언트 선택·명령 복사와 두 새 페이지의 모바일 배치도 확인했다.
25개 화면 점검을 통과했으며 브라우저 오류와 외부 HTTP 요청은 0건이다.
개인 토큰 동선은 별도 6개 점검에서 메뉴·설치 안내 간 이동, 모바일 배치, HTTPS 허브 경로의
발급 페이지 연결, 단일 HTML·잘못된 경로의 비활성 상태를 확인했다. 기존 다운로드 모듈에는
검증용 가상 API 응답을 넣어 파일명이 `user.token`이고 내용이 응답 토큰과 일치하는지 확인했다.
기존 웹 토큰 API 테스트 2개로 최초 발급·계정별 조회/폐기 분리·미허용 계정 차단도 확인했다.
이 검증에서 실제 Google 로그인이나 운영 토큰 발급은 하지 않았다.
데스크톱 1440px, 모바일 375px·320px에서 확인했다.
검증 결과와 데스크톱·모바일 스크린샷은 `.local/verification/ui-preview/`에 저장했다.
설치·배포 회귀 테스트 1개가 통과했고 안내의 명령 블록 7개는 `bash -n`으로 구문만 검사했다.
새 설치·실제 계산 작업·신청 전송을 실행하지 않았다.
`tests/test_api.py` 7개 테스트도 임시 SQLite DB에서 통과했다. 인증된 사용자별 서버 조회 분리,
요청 매개변수로 다른 사용자나 서버를 지정해도 권한을 넓힐 수 없음, 사용자의 자체 권한 확대 거부,
관리자에 의한 권한 회수 후 다음 조회에서 서버가 제외됨을 확인했다.
운영 데이터 연동·실제 Google 로그인·웹 배포 검증을 대신하지 않는다.
