# 229 SSH 실행 운영 검증

검증 시각: 2026-09-19 00:07 UTC. 메인 컨테이너 226에서 새 stdio MCP 연결을 열어,
운영 허브와 실제 SSH를 통해 229의 개인 컨테이너에 작업 두 건을 제출했다. 최종 시험은 통과했다.

## 환경과 요청

- 허브: `http://192.168.10.41:8080`, 사용자 `ezy`, UID/GID `1101:1100`.
- SSH: `ezy@203.255.11.229`, 포트 `11010`, 대상 호스트 이름 `fc5b36a891d5`.
- 승인된 환경: `9b207fd398494c479f5b4489a93bc22c`, 상태 `READY`.
- 새 MCP 연결에서 SSH 등록·제출을 포함한 도구 10개를 확인했다.
- 작업마다 CPU 1개, 메모리 128MiB, `NVIDIA GeForce RTX 3090` 한 장을 신청했다.
- 배정 GPU: `GPU-3e554084-64db-a82f-419a-4d75eece4e3b`.

두 명령은 CUDA 장치를 확인하고 GPU 메모리 4KiB에 값을 쓴 뒤 CPU로 복사해 일치 여부를 검사했다.
검사 후 A는 30초, B는 4초를 기다리고 정상 종료한다. A 실행 중 B를 제출해 같은 GPU에 대한
대기를 검증했다. GPU 장치 확인과 메모리 검사는 NVIDIA의
[장치 API](https://docs.nvidia.com/cuda/cuda-driver-api/group__CUDA__DEVICE.html)와
[메모리 API](https://docs.nvidia.com/cuda/cuda-driver-api/group__CUDA__MEM.html)를 사용했다.

## 기록과 범위

최종 기록은 `.local/verification/20260919T000740388185Z-ssh229/result.json`에 있다.
요청, 실제 명령 로그·실행기 기록 경로, GPU 검사 결과, 알림 상태를 포함하며 인증 비밀정보는 포함하지 않는다.
시험 코드는 `.local/verify_ssh_229.py`, 대상 명령은 `.local/gpu_probe_worker_timed.py`에 보존했다.

앞선 시험은 공유파일을 만들어 A의 대기를 해제하는 방식이었으나, 정해진 시간 내 종료를 확인하지 못했다.
두 시험 작업을 MCP로 취소했고 최종 `CANCELLED`와 알림 총 3건의 `SENT`를 확인했다.
공유파일의 NFS 가시성 지연은 가능한 원인이며 확정하지 않았다. 최종 시험에서는 대상 명령 자체의
짧은 타이머로 종료해 이 시험용 파일 신호에 의존하지 않았다. 앞선 기록은
`.local/verification/20260919T000437980230Z-ssh229/result.json`에 보존했다.

이번 시험은 229의 RTX 3090 한 장에 대한 예약·장치 선택·CUDA 메모리 접근과 SSH 실행 경로를 검증한다.
학습 성능, 큰 메모리 사용, 다른 GPU 모델, 여러 GPU 동시 계산, 224·228의 원격 실행은 검증하지 않았다.
CUDA 장치 가시성 설정은 협력적 예약의 일부이며 다른 작업의 GPU 접근을 강제로 차단하는 기능은 아니다.
접수 응답 유실을 강제로 일으키는 시험은 이번 운영 시험에 포함하지 않았으며 기존 자동 시험에서 다룬다.
