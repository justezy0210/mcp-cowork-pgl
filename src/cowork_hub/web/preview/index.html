GET STARTED
MCP 설치·사용
메인 컨테이너에 한 번 연결하고, 로컬과 SSH 환경에서 작업하세요.
Linux · Python 3.12+

        
접수 후에는 에이전트를 종료해도 됩니다.
실행기가 자원 대기·실행·종료 보고를 처리하고, 연결된 본인 Discord 채널에 시작·종료 알림이 갑니다.
서버 권한 신청

        

        

          
시작 전에 준비하세요
  • 관리자에게 등록된 본인 계정·서버 권한·UID/GID
  • 본인 개인 토큰 파일 발급·다운로드와 Discord 알림 채널
  • Git, Linux, Python 3.12 이상이 있는 메인 컨테이너
  • SSH 대상에서도 같은 절대 경로로 접근할 수 있는 본인 NFS 디렉터리
같은 사용자는 모든 컨테이너에서 UID/GID를 맞춥니다. 다른 사람과 UID를 공유하지 않습니다. SSH 대상에서도 설치에 사용한 Python을 실행할 수 있어야 합니다.

          
1본인 경로와 허브 주소 준비
아래 alice와 서버 ID를 본인 값으로 바꾸세요. 1~4단계는 같은 터미널에서 진행합니다. 새 터미널에서는 환경변수를 다시 설정해야 합니다. 허브 주소는 관리자에게 안내받은 값을 사용하세요.
메인 컨테이너 · 터미널
id -u
id -g
python3 --version

# alice와 226을 본인 공유 경로·메인 서버 ID로 변경하세요.
export COWORK_ROOT=/10Gdata/alice/cowork
export COWORK_HUB_URL=http://192.168.10.41:8080
export COWORK_NODE=226
export COWORK_WORKDIR=/10Gdata/alice/work
export COWORK_SOURCE="$COWORK_ROOT/source"
export COWORK_BIN="$COWORK_ROOT/client-0.1.0/venv/bin"

umask 077
mkdir -p "$COWORK_ROOT/state" "$COWORK_WORKDIR"
chmod 700 "$COWORK_ROOT/state"
curl --fail --max-time 5 "$COWORK_HUB_URL/healthz"
허브의 정상 응답은 연결 확인입니다. 본인 인증이나 실행환경 승인까지 완료된 것은 아닙니다.

          
2개인 토큰 준비와 클라이언트 설치
개인 토큰 발급·다운로드에서 본인 user.token을 받으세요. PC에 다운로드했다면 메인 컨테이너로 옮겨 $COWORK_ROOT/state/user.token에 준비합니다. 이미 본인 토큰이 있으면 그대로 사용하세요. 본인 소유 파일을 사용하며 토큰 내용은 명령 인자나 채팅에 넣지 않습니다.
메인 컨테이너 · 터미널
# 본인의 user.token을 state 폴더에 준비한 뒤 실행합니다.
chmod 600 "$COWORK_ROOT/state/user.token"
git clone https://github.com/justezy0210/mcp-cowork-pgl.git "$COWORK_SOURCE"
python3 "$COWORK_SOURCE/scripts/install_connector.py" \
  --prefix "$COWORK_ROOT/client-0.1.0"
installed: true가 성공 기준입니다. 기존 디렉터리가 있으면 덮어쓰지 말고 새 설치 경로를 정하세요. 실패한 설치를 다시 시도할 때도 새 경로를 사용하고 COWORK_BIN을 맞춥니다. 공유된 소스 폴더는 스킬이 참조하므로 보관하세요.

          
3메인 환경 등록과 관리자 승인
메인 컨테이너 · 터미널
"$COWORK_BIN/cowork-connector" configure \
  --hub-url "$COWORK_HUB_URL" \
  --token-file "$COWORK_ROOT/state/user.token" \
  --node "$COWORK_NODE" --workdir "$COWORK_WORKDIR" \
  --config "$COWORK_ROOT/state/connector.json"

"$COWORK_BIN/cowork-connector" start \
  --config "$COWORK_ROOT/state/connector.json"
"$COWORK_BIN/cowork-connector" status \
  --config "$COWORK_ROOT/state/connector.json"
등록 결과의 environment_id를 관리자에게 전달해 환경 승인을 받으세요. running: true는 연결 프로그램이 살아 있다는 뜻입니다. 허브 연결과 환경의 READY 상태는 다음 단계에서 확인합니다. 실행기 설정은 같은 폴더의 runner.json으로 생성됩니다.

5연결 확인
에이전트에 아래처럼 요청하세요.
cowork MCP로 내 서버 권한과 환경을 조회해줘. 메인 환경이 READY인지, Discord가 설정됐는지 확인해줘.
cluster_status, list_environments, notification_status로 확인할 수 있습니다. submit_job, cancel_job, register_ssh_environment도 보여야 합니다.
연결되면 에서 첫 작업을 확인하세요.

        

        

          
에이전트로 작업하기
실행환경이 READY이고 Discord 목적지가 설정된 뒤, 명령과 신청 자원을 함께 전달합니다.
메인 환경에서 /bin/echo cowork-ok를 CPU 1개, 메모리 64MiB로 실행해줘. 부족하면 대기열에 넣고, 접수 후에는 감시하지 말고 마무리해줘.
자원이 부족하면 에이전트가 대기·자원 축소·다른 준비된 서버 중 선택을 도울 수 있습니다. 접수된 작업은 별도 실행기가 진행합니다.

          
에이전트 없이 CLI로 작업하기
설치 단계의 환경변수가 설정된 메인 터미널에서 실행합니다. 위 에이전트 예시와 아래 CLI 중 하나만 선택하세요. 둘 다 실행하면 작업이 두 건 접수됩니다.
메인 컨테이너 · 터미널
"$COWORK_BIN/cowork-run" --config "$COWORK_ROOT/state/runner.json" \
  --cpus 1 --mem 64MiB --name first-test --detach -- /bin/echo cowork-ok
작업 ID와 로그 경로를 받고, Discord의 시작·종료 알림과 로그의 cowork-ok를 확인합니다. --detach를 쓰면 대기 중에도 터미널을 계속 열어둘 필요가 없습니다.
실제 분석 명령 예시
메인 컨테이너 · 터미널
"$COWORK_BIN/cowork-run" --config "$COWORK_ROOT/state/runner.json" \
  --cpus 8 --mem 32GiB --detach -- \
  python /10Gdata/alice/work/analysis.py --threads 8
--cpus 8은 허브 예약량이고 --threads 8은 분석 프로그램의 옵션입니다. 파일과 Python을 본인 환경에 맞게 준비하세요. GPU가 준비된 환경에서는 --gpus 1로 GPU 한 장을 예약할 수 있습니다. CLI는 자원이 부족하면 기다리며 자동으로 다른 서버를 선택하지 않습니다.

          
다른 서버를 SSH로 사용하기
메인 컨테이너에서 본인 계정으로 SSH 키 접속이 되어 있어야 합니다. 대상 서버의 사용 권한·동일 UID/GID·공유 경로도 필요합니다. 대상에는 별도 에이전트나 MCP를 설치하지 않아도 됩니다.
229 서버의 alice@203.255.11.229, SSH 포트 11010, 작업 경로 /10Gdata/alice/work를 cowork 환경으로 등록해줘.
계정·주소·포트를 본인 값으로 바꾸세요. 등록된 환경은 관리자의 승인을 받아 READY가 되어야 실행할 수 있습니다. MCP에서는 등록된 SSH 환경을 골라 제출합니다. 원격 컨테이너에서 수동 CLI를 쓸 때는 그 컨테이너의 실행기 설정을 사용하세요.

          
진행 확인과 취소
접수된 작업 ID로 에이전트에게 상태 조회나 취소를 요청하세요. 터미널·에이전트를 닫는 것은 취소가 아닙니다. 취소는 실제 상태가 CANCELLED가 되었는지 확인하세요. 컨테이너 중지는 작업 실행기도 중단시킬 수 있습니다.

        

        

          
막힌 단계부터 확인하세요
허브 연결 실패
메인·대상 컨테이너의 내부망 접근과 허브 주소를 확인하세요.
TOKEN_NOT_CONFIGURED · 인증 실패
본인 토큰 파일의 경로·소유자·0600 권한·유효성을 확인하세요. 토큰 내용은 공유하지 마세요.
FORBIDDEN_NODE
허용받은 서버인지 확인하고 서버 사용 신청을 준비하세요.
USER_IDENTITY_REQUIRED · IDENTITY_MISMATCH
관리자 등록 값과 id -u, id -g를 비교하세요. 같은 사용자는 모든 컨테이너에서 일치해야 합니다.
환경 승인 대기
등록된 environment_id를 관리자에게 전달하고 READY 상태를 확인하세요.
NOTIFICATION_NOT_CONFIGURED
본인 Discord 채널의 Webhook을 관리자가 허브에 연결해야 합니다.
SSH 등록 실패
SSH 키 접속, 알려진 호스트, 같은 공유 경로, 대상의 Python과 허브 접근을 확인하세요.
UNKNOWN · 접수 응답 불확실
기존 작업 ID·기록과 실제 프로세스를 먼저 확인하세요. 바로 재제출하면 중복 작업이 생길 수 있습니다.
컨테이너 재시작
본인 설정 경로로 cowork-connector start --config …를 다시 실행하세요. 자동 시작 스크립트 생성만으로 컨테이너 시작 절차에 연결되지는 않습니다.
